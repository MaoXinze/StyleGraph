# MMKG · 电商多模态知识图谱平台 — 实施蓝图

## 一、项目定位

**一句话**：以电商商品为载体，用 VLM 从「商品图 + 文本」中自动抽取实体与关系，构建多模态知识图谱（Neo4j），支持**以图搜款、搭配推荐、导购问答（GraphRAG）**三大能力，形成「数据构建 → 图谱存储 → 多模态检索 → 产品化应用 → 评估迭代」的完整闭环。

**不是玩具的保证**：
- 完整工程化：分层架构、可插拔模型层、断点续跑管线、限速重试、结构化日志、运行成本报告
- 评估驱动：属性抽取 F1、检索 Recall@K、问答评分集，每个版本有可对比的评估报告
- 产品形态：正式前端 + Docker 一键部署 + CI，README 可直接作为简历项目说明

## 三、图谱本体设计（Schema）

**节点**：
- `Product`：ASIN、标题、价格、评分、图片路径、构建状态字段（支持断点续跑）
- `Brand`、`Category`（三级类目树）、`AttributeValue`（facet=value，如 color=red、material=cotton）、`Occasion`（party/work/date…）
- `Outfit`：生成的搭配方案（含理由、点赞数 → 用户反馈回流）

**关系**：
- `HAS_BRAND` / `IN_CATEGORY` / `HAS_ATTRIBUTE {source, confidence}` / `SUITABLE_FOR`
- `CO_PURCHASED {weight}`（数据集共购信号，客观）
- `PAIRS_WITH {reason, confidence}`（VLM 抽取的搭配关系，带证据理由——图谱的"智能"所在）
- 向量：`Product` 挂 image_embedding(512d) + text_embedding，建 Neo4j 向量索引

## 四、构建管线（5 个阶段命令，均可断点续跑）

1. **ingest**：拉取 Amazon Reviews 2023 服装类目子集（1.2 万商品，过滤有图、有价格、评分数达标）→ 清洗去重（标题精确 + 图像感知哈希）→ 下载缩略图 → 商品/品牌/类目入图
2. **extract**：VLM 逐商品看图+标题 → JSON Schema 约束输出（颜色/材质/风格/季节/场合/性别/细分品类）→ pydantic 校验失败自动带错误重试 → 批量用低价模型、抽样用旗舰模型控成本
3. **relations**：候选对 = 共购 Top-K + 规则互补类目（上衣×下装×鞋）+ 向量近邻 → VLM 验证并生成 PAIRS_WITH 及理由（每商品限 2-4 对控调用量）
4. **embed**：CLIP 批量编码图+文 → 写入向量索引
5. **build-all**：编排全部，产出运行报告（成功/失败数、token、耗时）

## 五、三大智能应用

1. **以图搜款**：上传穿搭照 → VLM 检测多单品边界框 → 裁切逐件 CLIP 检索 → 可叠加属性过滤
2. **搭配推荐**：选中商品 → 图上多跳扩展（PAIRS_WITH + CO_PURCHASED + 风格/颜色一致性）→ LLM 生成搭配卡片（每件附理由）→ 存为 Outfit 节点
3. **导购问答（GraphRAG）**：中文自然语言 → LLM 解析为结构化查询意图 → 图查询 + 向量召回混合 → 带商品卡片和图谱依据的回答

## 六、评估体系（M5 重点，各版本留档）

- 抽取质量：抽样 200 商品属性抽取 P/R/F1（LLM 评审 + 人工抽查）
- 检索质量：留出商品图作 query，Recall@10 / MRR
- 搭配质量：PAIRS_WITH 正例 vs 随机负例排序 AUC
- 问答质量：30 条固定中文问句集，规则 + LLM 双评
- 依据评估结果迭代 prompt/模型/重排，形成"优化前 → 后"对比数据（简历叙事核心）

## 七、前端页面

首页（搜索+上传）｜以图搜款（检测框+逐单品结果）｜商品详情（图谱邻居可视化+"搭配它"）｜导购问答（chat+商品卡片）｜图谱探索（cytoscape.js 力导图）｜管理台（管线状态、抽取质检抽样审核页）

## 十、前置条件与磁盘布局

- 需要你提供：百炼 `DASHSCOPE_API_KEY`（写入 `.env`）
- **torch 零下载**：Python 3.12 + `torch==2.13.0+cu130` + pytorch cu130 索引，与 DevMind-AI-test、sentiment-plus 完全同版本，uv 直接从本地缓存复用 wheel，无任何下载
- **D 盘（约 8-9GB）**：新 venv 约 5-6GB（缓存本地复制）+ 商品图约 2GB + 数据集缓存约 1GB + node_modules 约 0.5GB；HF/uv 缓存一律用环境变量重定向到 D 盘项目目录
- **C 盘仅 Docker（约 2-3GB）**：如需完全不占 C 盘，Docker Desktop → Settings → Resources → Advanced → Disk image location 可迁到 D 盘（可选）
- 合规：Amazon Reviews 2023 为学术公开数据集，研究/演示用途，不直接爬取电商站点
- 成本控制：数万次 VLM 调用优先用百炼免费/低价模型，管线内置限速与预算上限
